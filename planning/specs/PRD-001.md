# Spec — PRD-001

## Objetivo observável / motivo
Definir Product como template reutilizável do catálogo, conforme BUSINESS_RULES/GLOSSARY/SCOPE e ADR010/013/017/022. Depende de ARC-002 liberado. O template preserva identidade, nome, descrição, preço sugerido em centavos e estado ativo. Produto não possui estoque; venda/snapshot e dinheiro recebido são contratos distintos.

## Escopo / contrato / fora de escopo
Adicionar somente pub struct Product em src-tauri/src/domain/mod.rs: campos públicos id:[u8;16], name:String, description:String, suggested_price_cents:i64, is_active:bool. Nome e descrição são texto bruto, sem trim/normalização; preço é inteiro, sem float/conversão/cálculo. Booleano representa o estado armazenado em memória, inclusive inativo; padrão de criação cabe a PRD-005. String para descrição é escolha técnica mínima de representação, sem regra de obrigatoriedade. Não adicionar derives, Debug/Display/Clone, construtor, validação, Default, UI, IO, Clock/UUID, SQL, deps, migration, estoque, venda ou snapshot. PRD-002/003 validam nome/preço; PRD-004..007 tratam banco/criação/alteração/desativação. Um valor representável não é evidência de que uma operação o aceita.

## Critérios de aceite / testes / coverage
RED: compilação dos testes reais falha somente E0432 Product ausente. GREEN: um teste tipa explicitamente os cinco campos e conserva ID, Unicode/aspas/CRLF/espaços, preço12345/MAXi64 e ativo/inativo. Dois doctests compile_fail impedem Debug/Display, seguindo os tipos existentes, sem dados financeiros reais. Tipo/fields não introduzem linhas executáveis ou branches: não inventar cobertura percentual de Product. Medir novamente domain/mod.rs inteiro pelos testes existentes, gate linhas/funções>=95; controle de instrumentação sem execução de domínio deve rejeitar o mesmo gate. LLVM stable sem branches, sem Rust global/statement/CI coverage reivindicados.
