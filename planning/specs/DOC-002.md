# DOC-002 — Validar mapa contra árvore real

## Objetivo observável

O mapa aponta para fontes existentes e cada arquivo versionado ou novo não ignorado pertence a uma área documentada. Um check local e o workflow de documentação verificam esse contrato.

## Motivo

O roadmap seleciona DOC-002 como primeira tarefa `todo`, sem predecessores. O mapa atual omite arquivos da raiz e `docs/traceability/`.

## Escopo / Fora de escopo

Atualizar o mapa, acrescentar um check PowerShell sem dependências, conectá-lo ao workflow existente e registrar estado/evidência. A instrução humana posterior autoriza publicação pública no GitHub e reforço do `.gitignore` para viabilizar o gate de CI. Fora de escopo: produto, runtime, versões Node/Rust, regras financeiras, novos requisitos e PR.

Paths reservados: `00-MAPA-DO-PROJETO.md`, `scripts/`, `.github/workflows/docs.yml`, `.gitignore`, `planning/specs/DOC-002.md`, `planning/work-items/BOOTSTRAP-INDEX.json` (somente DOC-002), `planning/ROADMAP.md` (estado da tarefa), `docs/traceability/REQUIREMENTS_MATRIX.md` (linha documental), `planning/PROGRESS_LOG.md` (append-only) e `planning/handoffs/DOC-002.md`.

## Dependências e rastreabilidade

Sem predecessor no roadmap. Requisito documental `mapa reflete a árvore` do work item existente. Invariantes financeiros e matrizes de segurança permanecem planejados, sem alegação de implementação.

## Plano de agentes

P-INT é o único escritor, executor de checks e committer. Configuração solicitada pelo humano: gpt-6.1-sol/ultra; configuração efetiva não exposta. P-MAP/gpt-6-luna/low recebe inventário read-only; P-REV/gpt-6-sol/medium recebe o diff após escrita. Escopos distintos, no máximo dois delegados, sem revisão duplicada. Retornos são E2; execução pelo Integrador é E3.

## Contrato

Entrada: paths na coluna Fonte da tabela do mapa e inventário `git ls-files --cached --others --exclude-standard`. Diretórios terminam em `/`; arquivos usam path exato, relativo à raiz. Saída: exit 0 e contagens quando todos os paths existem no inventário e todos os arquivos estão cobertos; exit não zero para fonte inexistente, arquivo fora do mapa ou inventário Git inválido. Conteúdo de arquivos e dados reais não é emitido. Diretórios agrupam documentos; o mapa não é uma lista de todos os arquivos internos.

## Critérios de aceite

1. Cada fonte da tabela corresponde a arquivo ou diretório com arquivo no inventário Git.
2. Todos os arquivos versionados ou novos não ignorados são cobertos pelo mapa, incluindo entrada, rastreabilidade, scripts e CI.
3. Check repetível sem dependência nova, chamado pelo workflow existente.
4. Casos negativos comprovam fonte ausente, arquivo sem área e arquivo versionado removido; entradas duplicadas do índice Git são deduplicadas.
5. Spec, work item, matriz documental, progress log, review, handoff e commit registram o resultado. `passes=false` até CI remoto verde no SHA atual.
6. Repositório público autorizado, remoto `origin`, `.gitignore` testado com artefatos sensíveis/locais e fontes/lockfiles preservados; inventário do histórico e checkout auditados antes do push.

## Testes previstos / coverage afetada

RED contra mapa antigo; GREEN após correção; fixtures temporárias sintéticas em `scripts/test-project-map.ps1`; teste de exclusão/preservação em `scripts/test-gitignore.ps1`; reprodução local dos checks do workflow; `git diff --check`; leitura do JSON e inspeção do diff. Coverage não aplicável: nenhum código de produto existe. Lint/typecheck/test Rust/TypeScript e smoke de aplicativo não aplicáveis a este diff documental.

## Segurança / evidência necessária

Inspeção do diff e busca local de padrões de segredos com saída somente de paths; nenhuma ferramenta instalada. Gitleaks/OSV/audits não executados, pois não estão configurados nesta fase. Evidência registra ambiente, versões, comando, resultado e SHA de base; o commit final é identificado pelo histórico Git. Nenhum conteúdo remoto ou capability novo.

## Riscos / gate humano

Cobertura por diretório não verifica semântica dos documentos internos. CI configurado não equivale a CI executado. Remoto não registrado; ações externas dependem da autorização humana exigida na solicitação.

## Definição de concluído

Todos os critérios locais, review sem P0/P1/P2 relevantes, documentação e commit atômico, mais run remoto verde no mesmo SHA. Sem remoto/CI: handoff honesto, status bloqueado, `passes=false` e nenhuma tarefa dependente iniciada.
