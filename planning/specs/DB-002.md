# Spec — DB-002: abrir banco SQLite vazio em arquivo

## Objetivo observável

O core Rust abre um banco SQLite em um caminho de arquivo absoluto informado pelo caller, criando-o quando ausente e permitindo reabrir o mesmo arquivo sem perder seus dados.

## Motivo

DB-001 fornece apenas conexões SQLite em memória para testes. O produto precisa de uma abertura em arquivo real antes de definir migrations e schema.

## Escopo e limites

Promover `rusqlite` 0.40.2 de dev-dependency para dependência normal, preservando pin exato, `default-features = false` e `bundled`, sem adicionar crates. Expor `millani_artes::database::open_database(&Path) -> Result<rusqlite::Connection, DatabaseOpenError>` em `src-tauri/src/lib.rs`, apontando diretamente para `infrastructure/database.rs`. Não exportar `infrastructure/mod.rs`, que acopla módulos de aplicação do binário.

O core aceita somente path absoluto e não vazio; o pai deve existir e ser controlado pelo caller. Rejeitar diretório. Usar flags `READ_WRITE | CREATE`, sem URI. Consultar `sqlite_schema` na abertura para forçar leitura do banco. Erros são estáticos, sem payload, `source` ou logging com SQL/path. O caller escolhe o path.

Fora de escopo: UI/IPC/default app-data, containment ou política de path, migrations, schema de produto, FK, transações, backup/restore, instalador e regras financeiras. A validação do path não constitui segurança global nem containment; esses contratos exigem specs próprias.

## Dependências e rastreabilidade

Depende de DB-001. Relaciona-se a ADR-003, ADR-023, `docs/architecture/DATA_MODEL.md`, `docs/product/SCOPE.md` e `docs/product/INVARIANTS.md`. DB-003 define executor de migration; DB-009 ativa FK; DB-011 define transação.

## Contrato: entradas, saídas, invariantes e erros

- Path absoluto escolhido pelo core; pai existente e sob responsabilidade do caller.
- Arquivo novo abre como SQLite utilizável e sem objetos de usuário em `sqlite_schema`; reabrir o mesmo arquivo mantém o banco válido.
- Arquivo existente preserva conteúdo. Dois paths diferentes são bancos independentes.
- Path vazio, relativo, diretório, arquivo inválido ou pai que seja arquivo retorna erro sanitizado. Falha não sobrescreve sentinela existente.
- `DatabaseOpenError` tem apresentação `Display`/`Debug` estática e não expõe path, SQL ou payload; não fornece causa via `source`.

## Critérios de aceite

1. API pública `millani_artes::database::open_database` tem a assinatura definida e abre arquivos reais com flags RW|CREATE sem URI.
2. Testes usam diretório único criado atomicamente com `std::fs::create_dir`, fixtures de arquivo reais e limpeza RAII restrita ao próprio diretório.
3. Testes cobrem criação vazia, reabertura, round-trip parametrizado do valor sintético `O'Brien`, arquivo independente, entradas inválidas, preservação de sentinelas e sanitização de erros.
4. `rusqlite` mantém versão e recursos; mudança do manifest é tratada como novo hash Cargo. Cargo Audit e OSV vinculam ambos `Cargo.toml` e `Cargo.lock`; o lock idêntico não preserva o escopo OSV quando o manifest muda. Records antigos permanecem intactos; novos escopos exigem scans e gates próprios.
5. Formatação, clippy, suíte Rust, harness release e checks de segurança/documentação/review apropriados passam; CI é verde no SHA final. Nenhum teste deste item usa somente memória como prova de abertura de arquivo.
