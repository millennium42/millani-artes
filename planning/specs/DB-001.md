# Spec — DB-001

## Objetivo e motivo

Criar conexão SQLite real, nova e limpa para testes Rust de integração. O roadmap liga DB-001 a INF-006; DB-002 escolherá como abrir o banco do produto. `TEST_STRATEGY.md` requer banco temporário limpo; este item usa SQLite em memória.

## Escopo e limites

Adicionar `rusqlite 0.40.2` exato como dev-dependency, `default-features = false`, recurso `bundled`, helper de teste compartilhado e um teste de integração. Cada chamada a `Connection::open_in_memory()` produz um banco isolado; `drop` encerra sua vida. Usar somente dados sintéticos e parâmetros SQL.

Sem banco/path do usuário, tempfile, migration, schema financeiro, versão, FK, transação, backup/restore, UI, WebView, regra financeira, FFI manual, Python SQLite, dependência adicional ou ajuste de threshold. O harness não comprova arquivo/durabilidade, permissões, containment, locks entre processos, migration, backup/restore ou comportamento do produto.

API registry não informa MSRV; projeto fixa Cargo 1.99. Metadata web não é prova de resolução, build ou audit. Não adicionar tempfile.

## Contrato e testes

Helper retorna `rusqlite::Result<Connection>` novo. O teste prova: (1) conexão sem objetos em `sqlite_schema`, contando todos os tipos de objeto; (2) tabela sintética e insert/select parametrizado retornam o valor exato sintético `O'Brien`; (3) segunda conexão simultânea não vê a tabela; (4) após descartar a primeira, nova conexão segue vazia. Registra a versão de SQLite retornada por `SELECT sqlite_version()`. Erros SQL propagam no teste; nenhuma estrutura persiste. O insert parametrizado é caso do harness, não prova global contra SQL injection.

RED E3 (root): helper inicialmente continha `todo!("SQLITE_HARNESS_MISSING")`; o target executou e falhou em runtime nesse stub. GREEN E3 (root): teste dedicado passou com SQLite 3.53.2. No bloco Build Tauri existente em `docs.yml`, após build, executar somente `cargo test --release --locked --manifest-path src-tauri/Cargo.toml --test sqlite_harness --features tauri/custom-protocol -- --nocapture`; falha encerra a etapa. Sem nova job/action/cache/upload ou runtime WebView. Perfil release existente pode ser reutilizado; rusqlite/SQLite bundled ainda adiciona compilação C ao target de teste. Sem mudança de coverage.

1. Pin exato, checksum e grafo Cargo registrados; wrapper é dev-only, sem default features, só `bundled`.
2. Helper e teste real provam os quatro comportamentos acima e registram a versão SQLite, sem dados reais.
3. Teste dedicado integrado ao Build Tauri existente e falhas propagam.
4. Root executa fmt, clippy, teste dedicado, suite Rust, audit/OSV crus e validators aplicáveis sem ignore, dispensa ou thresholds reduzidos. E4 aprovado só para os scopes acima; gates Cargo/OSV passaram nos inputs exatos aprovados, mantendo findings excepcionados registrados.
5. Review sem P0/P1/P2, aceite E4 aplicável e CI verde no SHA exato: executor `done`/`passes=true`; `humanGateRequired=true` até nota pública e liberação explícita.
