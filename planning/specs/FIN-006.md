# Spec — FIN-006

## Objetivo observável
Adicionar uma migration SQLite versionada que cria `main.accounts` com as quatro propriedades atuais de domínio de `Account`, e comprovar sua aplicação em banco vazio e upgrade de v2.

## Motivo
`Account` já contém ID, nome, `AccountType` e saldo inicial em centavos. FIN-006 é a primeira persistência de contas. ADR-013 define centavos inteiros e ADR-014 exige migrations versionadas, aditivas e imutáveis. ADR-024 estabelece abertura de arquivo; ADR-023 e o harness existente permitem executar testes com arquivos temporários controlados. Nenhuma regra comercial adicional é estabelecida nesta tarefa.

## Proposta de schema — requer review técnico antes de DDL
Proposta para `src-tauri/migrations/003-accounts.sql`, a ser revisada por P-DAT/P-REV antes de implementar SQL:

```sql
CREATE TABLE main.accounts (
    id BLOB NOT NULL PRIMARY KEY
        CHECK (typeof(id) = 'blob' AND length(id) = 16),
    name TEXT NOT NULL CHECK (name <> ''),
    account_type TEXT NOT NULL
        CHECK (account_type IN ('cash', 'bank_pix', 'card', 'other')),
    initial_balance_cents INTEGER NOT NULL
) STRICT;
```

A proposta cria somente as quatro colunas correspondentes aos campos públicos existentes. `cash`, `bank_pix`, `card` e `other` são chaves técnicas propostas derivadas das quatro variantes atuais `Cash`, `BankPix`, `Card` e `Other`; não são ordinais, nem regras financeiras novas. `initial_balance_cents` usa o range físico assinado i64 do SQLite INTEGER, sem decidir política comercial de sinal, limites, cálculo ou edição posterior. Não adiciona default, timestamps, índices, FK, seed nem colunas auxiliares.

`length(TEXT)` no SQLite para no primeiro U+0000. A implementação atual de `Account::validate_name` verifica `self.name.trim().is_empty()`, que aceita a string sintética `"\0Conta"`; a proposta anterior `length(name)>0` adicionava uma rejeição não aprovada. Review independente P-REV gpt-6-sol medium encontrou esse P2 e recomendou `CHECK (name <> '')`, com collation BINARY padrão; a igualdade rejeita somente string vazia e não rejeita prefixo NUL nem whitespace. A validação de whitespace Unicode permanece no domínio/FIN-008. Root verificou a correção e a aprovação técnica condicional E2 satisfez a etapa de review; nenhum DDL foi criado ou aplicado ainda. Fonte primária: [SQLite core functions — length](https://www.sqlite.org/lang_corefunc.html#length). Em tabelas STRICT, SQLite ainda pode aceitar valores convertíveis à classe declarada; os testes não devem afirmar que qualquer representação textual coercível é rejeitada. Sem gate de aceite humano registrado.
