# Spec — DB-013: evento técnico de auditoria SQLite

## Objetivo observável
Criar a migration versionada `002-audit-event.sql` e uma API de append que grava evento técnico na transação SQLite fornecida, sem commit próprio. Banco vazio percorre baseline versão 1 vazia até versão 2; upgrade preserva dados existentes.

## Motivo
`BUSINESS_RULES.md` exige histórico técnico suficiente para diagnóstico. `TRANSACTION_MODEL.md` exige que falha ao gravar audit_event cancele a mesma unidade financeira; DB-014 provará essa integração. ADR-014 determina migrations imutáveis e testadas.

## Escopo / fora de escopo
Adicionar migration aditiva e imutável, constantes exportadas `AUDIT_EVENT_MIGRATION_VERSION = 2` e `AUDIT_EVENT_MIGRATION_SQL`, e `append_audit_event(&Transaction, &AuditEvent) -> Result<(), AuditEventError>` no código existente de banco. Reusar `execute_versioned_migration`; versão 1 é baseline vazia registrada pelo executor existente. Não criar startup, registry ou auto-migrator. Testar banco vazio 0→1→2 e fixture versão 1 com probes preservados na atualização.

Fora de escopo: consumidores financeiros/DB-014, relógio ou adaptador UUID, logging, anti-tamper contra host que controla arquivo SQLite, nova dependência, mudança de workflow e edição de migration já aplicada.

## Contrato e critérios de aceite
`AuditEvent` contém `event_id: [u8;16]`, `occurred_at_ms: i64` (Unix ms UTC fornecido pelo chamador), `operation` e `entity` como `&'static str`, e `entity_id: [u8;16]`. IDs são bytes opacos, não UUID RFC validado nem garantia de unicidade do provider. Não incluir payload, dados financeiros ou conteúdo de debug.

Rust rejeita UUID nulo, timestamp negativo e tags fora de `^[a-z][a-z0-9_]{0,63}$`, inclusive NUL. Erros fechados `InvalidEvent` e `InsertFailed`; `Debug`/`Display` estáticos, sem fonte ou texto bruto do driver. SQLite armazena todos os campos `NOT NULL` explícitos; checa BLOB de 16 bytes não nulo, timestamp INTEGER ≥0 e tag TEXT ASCII de 1–64 bytes, início `[a-z]`, demais `[a-z0-9_]`, sem NUL. A tabela `main.audit_event` tem chave primária que rejeita duplicata sem overwrite e triggers BEFORE UPDATE/DELETE com `RAISE(ABORT)`. API usa INSERT comum e parâmetros vinculados.

Referências primárias: [SQLite CREATE TABLE](https://www.sqlite.org/lang_createtable.html) e [SQLite CREATE TRIGGER](https://www.sqlite.org/lang_createtrigger.html).

Cinco testes: `db013_audit_schema_initializes_empty_and_upgrades_file`; `db013_audit_event_persists_metadata`; `db013_audit_event_rejects_invalid_metadata_and_duplicates`; `db013_audit_schema_rejects_invalid_rows_and_mutations`; `db013_audit_errors_hide_driver_payload`. Verificar reopen/ledger 1 e 2, preservação dos probes, tipos/null/NUL/comprimentos/tags, UUID/timestamp, duplicata, update/delete e sanitização.
