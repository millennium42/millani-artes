# Spec — FIN-001

## Objetivo observável
Definir e compilar no domínio a identidade mínima de uma conta: `pub struct Account { pub id: [u8; 16], pub name: String }`. Um teste unitário preserva exatamente os 16 bytes opacos e o nome Unicode próprio.

## Motivo
O glossário define Conta como lugar que possui saldo. Esta tarefa estabelece somente identidade e metadado de nome para permitir evolução posterior sem antecipar regras financeiras.

## Escopo / Fora de escopo
Escopo: declarar `Account` diretamente em `src-tauri/src/domain/mod.rs`; incluir dois doctests `compile_fail` independentes, um para `Debug` e outro para `Display`, com limites genéricos somente de tipo; adicionar teste unitário em `src-tauri/src/domain/tests.rs`.

Fora de escopo: validação/normalização do nome (FIN-002), tipo de conta (FIN-003), saldo inicial em centavos (FIN-004), contexto, construtor, getters, derives, módulos/tipos auxiliares, SQLite, repositório, caso de uso, IPC ou UI. ID e nome são metadados opacos, sem validação nesta etapa.

## Contrato: entradas, saídas, invariantes, erros esperados
`Account` expõe somente `id: [u8; 16]` e `name: String`, ambos públicos. O ID é opaco; o nome é string UTF-8 própria. O chamador constrói por literal. Não se define validação, canonicalização, unicidade ou comportamento financeiro. `Account` não implementa `Debug` nem `Display`; doctests separados testam limites genéricos, sem depender de campos ausentes.

## Critérios de aceite
- Tipo público contém exatamente `id: [u8; 16]` e `name: String` no módulo de domínio existente.
- Teste unitário comprova preservação exata dos bytes e texto Unicode.
- Dois doctests `compile_fail` independentes comprovam ausência de `Debug` e `Display` usando somente limites genéricos de tipo.
- O aceite legado “contrato compilado e testado” permanece coberto pelos checks do integrador.
- Não entram validação de nome, tipo de conta ou saldo inicial de FIN-002/003/004, nem construtor, getter, derive ou tipo/módulo auxiliar.
